Every run writes `report.json` (stable schema) and `report.html` / `report.md`.

## A finding

```json title="report.json (one finding)"
{
  "id": "F-0031",
```

## Report-level fields

| Field | Content |
|---|---|
| `verdict` | `READY` / `NOT_READY` / `NEEDS_REVIEW` |
| `coverage` | Fields and visualizations matched vs total |
| `intentional_differences` | Mapping `ignore` entries with reasons |
| `llm` | Calls, cache hits, model per alias, prompt versions |

## Page order in the HTML report

<Steps>
1. **Blockers**, grouped by root cause, with the symptoms beneath
2. **Unverified** items and why they couldn't be decided
3. **Warnings**
4. **What was proven** (collapsed), so reviewers can see what was checked
5. **Look & feel** (low)
</Steps>

<Aside type="tip" title="Batch summary">
	Across many packages, a CSV/JSON summary shows pass rates and the most common failure types. This
	feeds back into developer guidance during the migration.
</Aside>
