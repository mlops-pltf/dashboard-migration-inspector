## Model: YAML export

`POST /api/model/dataModels/{id}/export` with `Accept: application/yaml` (Strategy April 2026+).
Returns one file with the whole model:

- **tables**: physical columns, data types, source `namespace` / `tableName` or custom `sql`
- **attributes**: forms, form expressions *with the tables they map to*, lookup tables, key form
- **factMetrics**: fact expression, `function`, `dimty` (level)
- **metrics**: expression text, e.g. `Sum([Revenue]){~+}`
- **hierarchy.relationships**, folders, links, external data models
- a **fingerprint** (checksum) for detecting changes

```yaml title="excerpt"
factMetrics:
  - information: { subType: fact_metric, name: Year Duration }
    fact:
      expressions:
        - expression: { text: year_duration }
          tables: [{ subType: logical_table, name: lu_year }]
    function: sum
    dimty:
      dimtyUnits:
        - { dimtyUnitType: report_base_level, aggregation: normal, filtering: apply, groupBy: true }
metrics:
  - information: { subType: metric, name: New Metric }
    expression:
      text: "Sum<UseLookupForAttributes=False>([Year Duration]){~+}"
```

## Dashboards: `.mstr`

One binary `.mstr` per dashboard, decoded by the Strategy expert's `mstr_reader` (format, evidence and known gaps
in its README). Objects in the `.mstr` join the model export by object id.

<Aside type="caution" title="No other Strategy input">
	No REST calls and no SQL from Strategy: everything the Inspector knows about the Strategy side comes from
	these two files. What they cannot express is reported as UNVERIFIED, never assumed.
</Aside>
