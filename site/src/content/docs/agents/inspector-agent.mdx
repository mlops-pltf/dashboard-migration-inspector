The Inspector never reads TML or Strategy files: the expert agents export each side as IR over A2A, and the
Inspector works on that. It decides what to investigate and concludes; its tools return exact answers; the
ledger makes sure every conclusion rests on evidence.

## A typical run

<Steps>
0. Before the agent starts, code runs the rule sweep and the data probes its leads carry, and loads the result
   into the ledger. Leads the data settled are facts the agent explains but cannot overturn.
1. `inspect_package`: contents, Strategy input format, what that format cannot carry.
2. `run_rule_sweep`: returns that result: **open leads** (marked `settled_by_data` where decided) and items **proven**.
3. `match_fields`: review the pairing, especially inferred or one-sided objects.
4. Investigate each lead with the tools that answer the real question, and group symptoms under one root cause.
5. Look beyond the leads: meaning the rules can't see, wrong matches, objects the format lost.
6. `request_data_probe` where only data can settle it.
7. `record_finding` for every conclusion, then `finalize_report` with a summary for the developer.
</Steps>

## Tools (18)

| Tool | Answers |
|---|---|
| `inspect_package` | What is in the package; format losses; parse problems |
| `run_rule_sweep` | All deterministic checks: open leads and proven items |
| `match_fields`, `find_counterparts` | Which ThoughtSpot field is which Strategy object, and why |
| `list_fields`, `get_object` | Either side's IR: fields, formulas, joins (with when applied), tables, SQL, dashboards |
| `ask_expert` | Ask the ThoughtSpot or Strategy expert what something means (opinion, not proof) |
| `trace_lineage` | A field down to warehouse columns (incl. join-key equivalents) |
| `compare_fields` | Proof of identical meaning, or what kind of difference |
| `analyze_sql` | Have an expert analyse a SELECT (lineage, joins, filters) |
| `get_join_graph`, `compare_joins` | Join types, keys, applicability on each side |
| `analyze_row_multiplication` | Fan-out and chasm traps inside Freeform SQL |
| `compare_filters` | Model-level filters on both sides, canonical |
| `compile_query` | The SQL either side computes for a measure × dimensions × filters |
| `request_data_probe` | Ask the data agent (KPI equivalence, key/orphan profiles, impact) |
| `record_finding`, `finalize_report` | Write the report under the evidence rules |

## Evidence rules (enforced, not requested)

| Rule | Enforced by |
|---|---|
| Every analysis result gets an evidence id | an after-tool hook registers it in the ledger |
| A finding must cite evidence | `record_finding` refuses otherwise |
| A **blocker PASS** needs proof: `compare_fields` identical, an item the rules proved, or matching data | `record_finding` |
| A rule **FAIL** can only be softened with data | `record_finding` |
| A lead **settled by data** before the run keeps its status and severity | `record_finding` |
| Every open lead must be resolved | `finalize_report` refuses otherwise |
| The verdict is computed from findings | the ledger, never the model |
| The summary may not state a verdict | the ledger removes lines that do |

If the run ends early (turn budget, model error), the ledger finalizes anyway: unresolved leads keep their
rule result and are marked *not reviewed by the agent*.

## A2A interface

| Request | Answered by |
|---|---|
| Structured skill `validate` `{package, mode: agent \| rules \| rules+data, max_turns}` | Code (the agent runs inside) and returns report JSON + Markdown, the trace id and link, and the run folder |
| Any text message | The Inspector agent, with its tools (ask about a package or a finding) |

Package locations are folders under `PACKAGE_ROOT` locally, or `s3://` prefixes on AgentCore.

<Aside type="note" title="Testing">
	Tools and ledger have deterministic tests. Inspector tests run against the real expert agents in-process over A2A. The agent is scored on the 18 synthetic scenarios by a
	live evaluation (recall, precision, must-pass fields, every lead resolved) once a model is configured.
</Aside>
