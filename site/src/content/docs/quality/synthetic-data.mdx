## Warehouse with traps

A retail domain on `analytics.retail`, seeded so that **every injected defect produces a visible
numeric difference**:

	<Card title="Tables" icon="list-format">

		`dim_customer` · `dim_store` · `dim_product` · `dim_date` (fiscal year from April; Monday and

## What a package contains

<FileTree>
- synthetic/
  - packages/ **Inspector's input**
    - S04/
      - manifest.yaml
      - thoughtspot/ Table, Worksheet/Model, Liveboard, Answer TML
        - sql/ ThoughtSpot SQL per visualization
      - strategy/
        - model.yaml or model/\*.json or model.ossie.yaml
        - dashboards/
        - sql/model_sqlview.json
  - ground_truth/ **eval only, never read by Inspector**
    - S04/
      - expected_findings.yaml verdict, findings, root causes, must_pass
      - witnesses/ ThoughtSpot vs Strategy query pairs
  - warehouse/ CSVs, Postgres init scripts, Redshift DDL
</FileTree>

Ground truth sits **outside** the packages, so nothing Inspector or its LLM reads can give away the
answer. A test enforces this too.

## How each scenario is built

Every field in the generator carries three views of the same meaning: the **ThoughtSpot formula**,
the **Strategy definition** a correct developer would build, and its **true SQL semantics**. A
scenario corrupts the Strategy side (definition and SQL together). The package and the witness
queries then come from the same source, so they can't disagree.

<Steps>
1. Pick a ThoughtSpot model: **Sales Orders** (Worksheet TML), **Order Lines** (Model TML) or **Returns Analysis** (Model TML, two facts).
2. Build the Strategy version: lookup tables (attributes spanning tables define the joins) or one Freeform SQL table (`physicalTable.type: "sql"`).
3. Inject the defect, and record expected findings and the fields that must still pass.
4. Emit witness pairs and run them against the warehouse: defects must **differ**, benign changes must **match**.
</Steps>

## Running it

```bash
cd synthetic && uv sync
uv run inspector-synth warehouse      # CSVs + Postgres init scripts
docker compose up -d warehouse        # from the repo root; seeded on first start (:5439)
uv run inspector-synth generate       # packages/ + ground_truth/
uv run inspector-synth verify         # 25/25 witnesses behave as expected
uv run pytest                         # determinism, parsing, no leakage, traps, witnesses
```

<Aside type="caution" title="Synthetic assumptions">
	The dashboard JSON (A1), how lookup-style join semantics are declared (A2) and the Ossie YAML
	layout (A5) are modelled on our best information. They will be adjusted when a real sanitised
	export arrives. See [Assumptions & risks](/plan/risks/).
</Aside>

<Aside type="tip" title="The regression gate">
	`eval/` will run every scenario through both agents and score detection per check ID (recall,
	precision, verdict accuracy), LLM calls and runtime. Any change to parsers, prompts, models or the
	join-semantics profile has to pass it.
</Aside>
